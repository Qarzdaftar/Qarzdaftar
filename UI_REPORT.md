# QARZ DAFTAR — frontend/API handoff (local only)

## Architecture and contract

- Express 5/TypeScript (`src/app.ts`) serves readable public `public/index.html`, private `public/app.html`, static `public/assets/styles.css` and `public/assets/app.js`. No frontend build pipeline or separate frontend server. `npm run build` typechecks backend; ship `public/` alongside `dist/`. PostgreSQL/Drizzle owns balances, payment locking, store scoping and subscription state. UI never grants a role or activates a subscription itself.
- Public SEO: title/description, visible features/FAQs/pricing and truthful SoftwareApplication offers. Without a verified HTTPS `PUBLIC_ORIGIN`, `/` is noindex, `/robots.txt` disallows all and sitemap is 404. With verified origin, server injects canonical and serves public-root-only sitemap; `/app` stays noindex. No live indexing, AI citation or production domain is claimed.
- Private app consumes `{data}` / `{error:{code,message}}` REST responses from `src/app.ts` (details in README.md and SUBSCRIPTION.md). Signup/login return httpOnly session cookie and CSRF token, refresh uses `/api/auth/csrf`; mutations include token. Dashboard reads `/reports/summary?days=7|30|365`, `/debts`, `/payments`, `/customers`. Admin-only JSON export button downloads `/api/export` with cookies; the export contains customer phone numbers, so store it securely. List tables are limited to 100 newest records, but export includes all records currently (not streamed). Server controls authorization.
- Store admin gets SMS settings/outbox, audit, employee creation, subscription history and export; employee gets ledger routes. Platform owner aggregate is intentionally gated in browser because only server-to-server bearer auth exists; never insert `PLATFORM_REPORT_TOKEN` into JavaScript. Customer verified-phone self-view is absent because OTP is not implemented. Paid checkout controls are disabled when provider is unavailable; SMS banner states it is not live and separately priced. No actual charges or messages were sent.

## Local commands and verification

From this project directory: `npm ci`, `npm run build`, `npm run test:db`. The DB runner creates an isolated loopback PostgreSQL fixture, applies migrations, runs Vitest and cleans it up. This run: build passed, 3 files/17 tests passed on real PostgreSQL, JavaScript syntax and Python compile checks passed. Coverage includes ledger payments/overpay/idempotency/reversal, tenants/CSRF, SMS outbox status/duplicate/opt-out, trial/Payme synthetic callback. No provider sandbox or live merchant tests.

Browser fixture: `node scripts/browser-qa.mjs` starts isolated PostgreSQL and app at `127.0.0.1:4310` after build. An isolated Chrome DevTools endpoint on loopback `127.0.0.1:9229` is needed for `python scripts/chrome-qa.py`; use a dedicated disposable Chrome profile and close both processes after QA. This run used an existing isolated headless Chrome 154/CDP and local fixture, NOT Behruz's visible Chrome session. The script performed register → customer (including duplicate error) → 150000 UZS debt → 50000 UZS payment → 100000 UZS remainder, clicked admin export and parsed its downloaded JSON from the real DB, checked trial pricing and gated checkout/SMS/platform, audit and logout. It checked no horizontal overflow at 320/390/768/1440 px, private noindex and the reduced-motion computed scroll behavior. Screenshots `qa/landing-{320,390,768,desktop}.png`, `qa/dashboard-{320,390,768,desktop}.png`; landing-320, dashboard-390 and landing-desktop inspected visually. `GET /` and `/app` returned 200, local sitemap 404 by design. `:focus-visible` styling exists, but real assistive technology and keyboard-only session were not comprehensively tested; downstream QA should test them.
